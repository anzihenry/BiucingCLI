# 架构契约与设备验收

适用工程：`{{PROJECT_NAME}}`。这是生成后的验收清单，不是当前工程已经通过测试的证明。

## 会话与生命周期

每个 WindowStage 创建 SessionOwner，通过局部 LocalStorage 向页面传递 HomeModel；组件不访问全局容器。页面隐藏和进入后台不关闭，stage/ability 销毁时显式关闭并记录完成或错误。

业务示例是短时计算：临时遮挡和后台事件不主动销毁会话或取消已提交操作；不申请后台持续执行权限，
不承诺系统挂起或杀进程时继续执行。重新启动创建新会话，目前没有持久化状态恢复。
独立窗口/业务所有者使用独立会话，需要共享的数据应通过显式服务共享。
UI 界面仅发出类型化导航意图，焦点/滚动归 UI，业务结果和忙碌状态归 HomeModel。

## 设备范围

一个 entry 覆盖 phone/tablet/2in1/wearable/tv；Mobile、Desktop、Watch、TV 界面分别组织，业务模型共用。

设备声明不表示支持所有系统版本或应用模型。各设备需要明确功能范围与不适用项，
不得把 SDK 切片编译、宿主测试或模拟器结果推断为目标真机已经通过。

## DI 保证与缺口

组件内部与壳图分别检查；公共 SDK API 不暴露 DI 工具类型。缺失绑定、重复绑定、非法环路和
真实构造调用类型不匹配需要在构建阶段失败。描述图不等于对任意业务代码的完整静态证明。
应用/会话/功能所有权仍需行为测试验证，尤其是长寿命对象捕获短寿命会话、嵌套依赖与异步资源释放。
不要将测试通过表述成完整的编译期作用域保证。

可复现入口（先完成 SDK/组件 bootstrap；DI 反例在可丢弃生成工程中执行，不与其他构建并行）：

```sh
make verify-di
make verify-di-types
make test-native
make test
make build-device-tests
```

## 共同场景

| 场景 | 验收条件 |
| --- | --- |
| L01 | 重绘、配置变化和临时遮挡保留同一业务会话及结果，不重复创建核心 |
| L02 | 后台事件遵循上述策略，不仅因不可见就销毁会话 |
| L03 | 退出后拒绝新工作、取消活动工作、等待结束再释放；关闭幂等；过期结果不更新新页面 |
| L04 | 独立所有者互不影响；同一所有者的嵌套依赖使用同一受管服务 |
| L05 | 进程重启创建新句柄；持久化恢复不适用于当前无数据库示例 |
| I01 | 组件/壳分别执行缺失、重复、环路及类型错误反例，按预期原因失败 |
| I02/I03 | 嵌套作用域一致，跨会话隔离；关闭等待与资源释放有行为证据 |
| I04 | 发布 SDK 无源码可消费，描述/真实接口漂移会失败，公开 API 独立于 DI 工具 |
| M01 | 目标设备的触控/布局、键鼠/窗口、圆屏/旋钮或遥控器/焦点及无障碍验收 |
| V01 | 保存版本、环境、场景、结果、日志位置和未完成项 |

## 支持状态

按设备与构建类型分别填写 `verification-record.example.json` 的副本，不将示例中的 `not_run` 改成笼统通过。
V1=架构纳入；V2=构建通过；V3=指定环境运行通过；V4=目标真机适配通过；V5=签名、升级和分发就绪。
升一级必须完成对应阶段的全部适用场景；局部测试通过仅记录该场景。
关闭/资源单元测试不代替真实 UI 导航、窗口关闭和系统进程重建测试。
