## Getting Started

```bash
make bootstrap
make doctor
make verify-supply-chain
make lint
make test
make build
make artifact-info
make verify
make release-preflight
make verify-release-artifact
make release
```

`make doctor` checks Node.js, ohpm, hvigor or hvigorw, `DEVECO_SDK_HOME`, and common HarmonyOS SDK environment variables before you spend time on a build.
For a default macOS DevEco Studio install, the CLI build environment usually looks like:

```bash
export PATH="/Applications/DevEco-Studio.app/Contents/tools/ohpm/bin:/Applications/DevEco-Studio.app/Contents/tools/hvigor/bin:$PATH"
export DEVECO_SDK_HOME="/Applications/DevEco-Studio.app/Contents/sdk"
export HOS_SDK_HOME="/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony"
```
Open the project with DevEco Studio when you need signing, device management, previewer, or emulator workflows.
`make bootstrap` first verifies exact ohpm versions, the approved registry, and every lockfile SHA-512 integrity value; it fails if installation rewrites the lockfile. `make test` runs the starter Hypium suite through `hvigorw test`. `make build` creates an unsigned HAP by default. `make artifact-info` verifies the latest HAP exists, is non-empty, and prints its checksum. `make verify` includes the supply-chain gate before `doctor`, `lint`, `test`, `build`, and `artifact-info`. `make release-preflight` checks local signing material and rejects signing values left in the tracked build profile. `make release` requires a clean tracked `build-profile.json5`, temporarily injects release signing config, runs hvigor with `buildMode=release`, verifies the signed HAP, and restores the exact original profile on exit.

## Worktree Workflow

Each worktree derives a human-readable `WORKTREE_LABEL` from its directory name
and a hash-based `WORKTREE_ID` from the worktree root path. Override
`WORKTREE_ID` when you want a shorter or stable value across renamed folders:

```bash
WORKTREE_ID=feature-a make worktree-info
WORKTREE_ID=feature-a make worktree-debug-identity
WORKTREE_ID=feature-a make build
WORKTREE_ID=feature-a make clean-worktree
```

`make worktree-info` prints the isolated hvigor, ohpm, `oh_modules`, module
build, and signing-file paths. `make worktree-doctor` checks that tool caches
stay inside this worktree and reminds you that `local.properties` is local-only
signing material.

`make worktree-debug-identity` prints the base bundle name, requested
`DEBUG_BUNDLE_SUFFIX`, diagnostic debug bundle name, and hvigor properties. It
is intentionally read-only: `AppScope/app.json5` remains the source of truth for
`bundleName`. Automatic per-worktree bundle rewriting is deferred until the
DevEco/hvigor app metadata hook is verified on a configured HarmonyOS
workstation.

## Testing

The generated starter exposes `make test` through `hvigorw test --mode module -p module={{HARMONY_MODULE_NAME}}`. The template includes `@ohos/hypium` as a dev dependency and a starter smoke suite at `entry/src/test/List.test.ets`. Run `make bootstrap` before `make test` so ohpm can install test dependencies.

`make verify` treats tests as a required release-readiness gate. If the local ohpm registry, SDK, or Hypium dependency is unavailable, the test command fails with a clear setup message instead of silently skipping tests.

## Linting

`make lint` is a project guard, not a full ArkTS linter. It validates `code-linter.json5`, required HarmonyOS source/config files, and unrendered template placeholders. DevEco Studio remains the full lint surface until a stable public CLI lint or format command is verified for generated HAP projects.

## Release Signing

Local builds produce an unsigned HAP unless signing is configured. Use DevEco Studio for interactive signing setup, or copy `docs/release-signing.local.properties.example` to `local.properties` for local-only signing values. Put `.cer`, `.p7b`, and `.p12` signing material under the ignored `signing/` directory. `make release-preflight` fails fast when required values are missing, paths do not resolve, or signing material remains in tracked `build-profile.json5`.

`make release` stores a mode-restricted backup under the ignored `.biucing/release/` directory, writes the injected profile atomically, and restores the original bytes after success, build failure, `HUP`, `INT`, or `TERM`. Before reporting success it uses the SDK's `hap-sign-tool verify-app` and `verify-profile` commands, compares the embedded signer certificate and profile with the configured inputs, and verifies the profile's bundle name is exactly `{{BUNDLE_NAME}}`. Any mismatch fails the release. `SIGKILL` cannot run cleanup handlers; the next preflight detects a non-empty signing configuration. Do not stage Git changes concurrently with a signed release build.

Set `HAP_SIGN_TOOL` only when the SDK tool cannot be found under `DEVECO_SDK_HOME` or the default DevEco Studio installation. CI should point it at the reviewed SDK's `hap-sign-tool.jar`, not an arbitrary replacement.

The ignore rules also protect `credentials/`, private-key containers, and local environment files. They only apply to untracked files and do not override `git add -f`. If a real credential has already been committed, revoke or rotate it first, remove it from the index, and assess whether repository history must be rewritten.

## Pre-Distribution Coverage

The template intentionally stops before app-market upload or enterprise distribution. Before that handoff, the supported local stages are:

- `make bootstrap`: verify the lockfile, install HarmonyOS dependencies, and reject lockfile drift.
- `make verify-supply-chain`: enforce exact package versions, approved ohpm registry URLs, and SHA-512 integrity values.
- `make doctor`: verify DevEco Studio, Node.js, ohpm, hvigor, and SDK paths.
- `make lint`: validate committed lint/config shape and generated template integrity.
- `make test`: run ArkTS/Hypium CLI tests.
- `make build`: produce an unsigned HAP.
- `make artifact-info`: verify and fingerprint the package artifact.
- `make release-preflight`: verify signing material is present.
- `make verify-release-artifact`: cryptographically verify a signed HAP, signer, profile, and bundle identity.
- `make release`: produce and verify a release HAP when signing material is configured.

## Notes

- `oh-package.json5` is the project dependency manifest; dependencies must use exact versions and stay aligned with `oh-package-lock.json5`.
- `build-profile.json5` declares the app signing placeholder and entry module.
- `code-linter.json5` is committed so DevEco Studio and later CLI lint wiring share one rule source.
- `docs/release-signing.local.properties.example` documents placeholder-only local signing keys; `local.properties`, `signing/`, `credentials/`, and `.biucing/` are git-ignored.
- The generated starter keeps app metadata in `AppConfig` and visual constants in `core/designsystem` so feature pages do not duplicate bundle, version, spacing, or color values.
- Signing is left to DevEco Studio or CI-specific `local.properties` configuration.
- Keep `bundleName`, module name, and SDK versions aligned with your target HarmonyOS release channel before store packaging.
