# P5 高可用演练清单

只在已授权的隔离预生产环境操作。先确认 context、namespace、服务身份、测试数据、流量来源和可恢复备份；禁止把下面的故障动作默认指向生产。脚本 `kube-evidence` 只读，不会执行故障。没有目标集群/跨区资源/托管PG时 B27 保持待验收。

每次演练先保存只读快照，在整个时间窗内从集群外发送带 request_id 的持续 HTTP/mTLS 流量，记录成功/失败数、状态码、p95/p99、超时及实际完成的写入/查询确认。Micro 至少测试一条长期复用的 gRPC 连接；只测每请求建连会漏掉真实路由行为。fixture 必须与业务实现分离，不把测试写接口加到默认生产 API。

| 场景 | 故障注入与观察 | 恢复与验收证据 |
| --- | --- | --- |
| 错误发布 | 用可追溯的故障候选 digest 测签名拒绝；再用获准签名但无法 ready 的候选测试 rollout | 迁移失败时 Deployment 不更新；不就绪候选不记成功；兼容旧 bundle 回退；真实请求错误窗口与 schema 状态 |
| 节点维护 | 选中一个承载本服务的节点，使用平台受控 drain/Eviction API；禁止用强制删除绕过 PDB | 验证 PDB 阻止第二次不安全 eviction、EndpointSlice 摘流、在途请求排空、其他节点容量；结束后 uncordon |
| 节点突然失联 | 平台停止隔离节点或隔离其网络；不要仅用删 Pod 冒充节点故障 | 记录故障发现/Pod重建/路由恢复时间、存量RPC连接、丢请求；验证失联节点上的旧连接/写入风险与平台 fencing |
| 一个可用区失效 | 平台隔离该区节点和区内入口/出口依赖；本地多容器 kind 不能代表 AZ 故障 | 剩余域真实容量、调度 Pending、入口/DNS/registry/数据库单点、可恢复时间和人工步骤 |
| 托管 PG writer 切换 | 使用提供方预生产 failover 操作，保留连续数据写入和确认流水 | 记录 promoted writer、复制lag、DNS/连接重建、ready/live、错误/不确定提交、唯一写者及数据一致性；不能凭HTTP恢复证明零数据损失 |
| PKI 与入口证书轮换 | 重叠信任根→新叶证书/Secret版本→移除旧根，按调用链逐步验证新握手 | 合法新证书通过，旧/过期/错误URI或未经授权身份拒绝；检查已有连接的撤销窗口；入口TLS外部探测 |
| 恢复与重建 | 从独立故障域取回受校验的加密备份，在新隔离PG恢复，重新部署版本化配置/镜像 | 比对数据库关键数据/权限/schema/会话策略，测备份数据点及恢复时长；不覆盖原库；测试新入口切换和回退 |
| HPA/资源压力 | 可控增压和缓慢减压，再叠加节点不可用与慢依赖 | max副本、surge/terminating连接、池等待、CPU throttling、拒绝/超时、抖动；证明数据库连接预算和 N-1 容量足够 |

每步设定停止条件：错误或连接饱和超过预先约定窗口、数据一致性异常、剩余容量不足或失去唯一写者证明时停止新增故障。恢复节点/网络/入口前确认不会引入双写；不要同时盲目执行回退、强制schema版本与数据库切换。

将实际环境、镜像 digest、部署版本、入口/CNI/DNS/PKI/PG提供方、流量模型、开始/注入/恢复UTC、失败窗口、人工操作、数据验证与证据文件填写到 `drill-report.json`。保留 failed/not-run，不把缺项当零错误；RPO/RTO/可用性目标在有测量之后讨论。平台的凭据、完整 kubeconfig 和真实 Secret 不进入报告或仓库。
