# {{PROJECT_NAME}}

Customer-facing HTTP API generated by BiucingCLI.
P1 provides the runtime foundation. PostgreSQL adapters, migrations, OIDC, sessions,
mTLS and production deployment are implemented in later architecture stages.
Do not treat this starter as an authenticated production deployment.

## Docker workflow

Prerequisites: Docker Engine/Desktop with Compose v2.20+, Git and a POSIX environment with Bash.
No host Go, Buf, lint tool or Make installation is required. Run:

```sh
./scripts/task bootstrap
./scripts/task dev
./scripts/task logs
./scripts/task verify
./scripts/task image
./scripts/task down
```

`make bootstrap`, `make dev`, `make verify` and other Make targets are optional wrappers.
`bootstrap` builds the dev image and initializes only the project's cache/output ownership.
Containers use the calling user's UID/GID; shared source is mounted, generated files remain writable.
Air reloads Go/YAML edits, sends SIGINT before replacement and waits up to 12 seconds.
Go VCS auto-discovery is disabled inside containers because a worktree's `.git` file references
host paths; runtime image build information is supplied explicitly at build time.

| Command | Meaning |
| --- | --- |
| bootstrap | Build dev tools and initialize cache/output permissions |
| dev / up | Start development containers in the background; print assigned HTTP endpoint |
| logs / down | Follow logs / stop containers, retain data volumes |
| doctor | Check Docker, Compose and actual application configuration |
| lint / test / build / verify | Container checks; tests include Go race detection |
| image / docker-build | Build runtime image; optional VERSION, COMMIT, BUILT_AT, DOCKER_PLATFORM |
| docker-run | Run the built image with standalone root compose.yaml |
| migrate | Fail explicitly until B10 adds a real migration runner |
| worktree-info / worktree-doctor | Show project identity, assigned ports and running services |
| worktree-compose-config | Print development Compose configuration; local dev DSNs may be visible |
| clean | Alias for down, retains data |
| clean-worktree | Delete this project's data/cache volumes only with CONFIRM_DELETE_DATA=yes |

Development uses **only** `compose.dev.yaml`; runtime testing uses **only** `compose.yaml`.
These are standalone files, not overlays. Production configuration remains B20 work.

Old `make up` now starts in the background; use `make logs` to follow it.
`DOCKER_VARIANT=ubuntu`, custom `BUILDER_IMAGE` / `RUNTIME_IMAGE`, `GOPROXY` and `GOSUMDB`
remain available for image builds. Development tool images stay pinned.
`docker-run` starts the last built IMAGE:TAG, and may build it if it is absent; it is not a production deploy command.

## Worktree isolation

Project identity includes the Git worktree's absolute path checksum. Containers, networks,
cache/data volumes and image tags are scoped to that project. Host application ports default
to **0** (Docker assigns an available loopback port), so two worktrees can run concurrently.
Override HOST_PORT if a fixed port is needed.

Database, cache, Collector and admin ports are not published. Use Compose exec for administration.
Never run the destructive cleanup against a production Compose project.

## Configuration and secrets

Configuration order: selected CONFIG_FILE YAML → defaults for omitted fields → documented environment overrides.
Unknown YAML fields, invalid environment/ports/request limits/log levels are rejected before listeners open.
Overrides: APP_ENV, HTTP_PORT, ADMIN_ADDR, LOG_LEVEL, DATABASE_DSN and CACHE_DSN.
SERVICE_NAME is also supported.

Secret values may come from DATABASE_DSN_FILE or CACHE_DSN_FILE. Supplying both a direct variable
and its _FILE form is an error even if the direct variable is empty. Files are limited to 64 KiB;
one trailing newline is removed. Values are read at startup; rotate the mounted file and restart
instances deliberately. There is no implicit hot reload of secrets. `.secrets/`, `.env*` and private
`.key` files must stay outside Git and image contexts.

APP_ENV=production rejects inherited development DSNs: enabled components need an explicitly supplied
secret, PostgreSQL requires sslmode=verify-full and rejects the starter password; Redis requires rediss.
These guards do not implement a production secret manager or certificate issuer.
Avoid `compose config` on a production environment containing raw secrets.

`/app/server check-config` validates without opening listeners and prints an allowlisted summary.
It never prints DSNs or credentials. The executable supports no automatic migrations.

Database: `{{DATABASE}}`; cache: `{{CACHE}}`. They remain independent components; no data adapter
or session store is implemented in P1. Old dependency_store/--dependency-store and STORE_DSN are removed:
use database=postgres/cache=none, or database=none/cache=redis for Micro. Web generation requires PostgreSQL.

## Request and identity boundary

HTTP request bodies default to 1 MiB, process concurrency to 64 and deadline to 5 seconds.
Overload returns 429, oversized body 413, unauthenticated access 401, denied principal 403,
handler panic 500 and response timeout 503. TimeoutHandler uses 503 for its timeout response.
Cancellation reaches handlers; code must honor context. If a handler ignores cancellation,
its admission slot remains occupied until it exits, preventing unbounded work growth.
Streaming HTTP is not supported by the buffered timeout wrapper; enable it deliberately in E07.

Only GET /api/v1/ping is explicitly public as a technical fixture. Other routes default to denial.
Principal values can only be installed by a credential verifier through the security package;
X-User-ID, cookies and bearer strings do not become trusted identities by themselves.
Policy hooks are deny-by-default; OIDC/mTLS verifiers arrive in P2. Do not add a header-based bypass.

## Health and lifecycle

Admin listener defaults to **127.0.0.1:9000 inside the container**, separate from application traffic.
It serves /livez, /readyz, /version; /healthz is an admin-only compatibility alias. No pprof or metrics
endpoint is exposed in P1. B18 adds metrics on the management surface.
A public /healthz request no longer returns health information. Probe with Docker exec:

```sh
# runtime image
/app/server healthcheck http://127.0.0.1:9000/readyz
```

Liveness does not query dependencies. Readiness tracks startup/drain and registered critical checks;
optional telemetry is never a readiness prerequisite. Critical checks must honor their context.
SIGINT/SIGTERM marks readiness false, stops admission and drains within server.shutdown_timeout_seconds;
remaining connections are closed after the budget. Partial bind failures close earlier listeners.
No sticky sessions or database availability are implied by a successful probe.

## Logs and audit

JSON slog logs use configured levels, request IDs, route templates, status codes and duration.
Bodies, query strings, cookies, tokens, raw errors and panic values are excluded from request events.
Sensitive structured keys are redacted as defense in depth; never put secrets in free-form log messages.
Audit events carry kind=audit and an allow/deny outcome; access events carry kind=access.
Access/audit output shares a 100-event/second process budget; drops are summarized on the next active
window. This audit hook is not a lossless compliance ledger. Platform storage/retention and B18 trace
instrumentation remain separate responsibilities. Standard output backpressure is managed by the runtime;
P1 does not introduce an unbounded asynchronous log queue.

Run ./scripts/verify-container for an isolated container verification run, including failed-run cleanup.
The generated CI calls the same entry point. Request, secret, admission, startup and drain regressions
are exercised with real Go tests; production identity/database claims require later integration gates.
