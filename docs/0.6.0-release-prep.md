# BiucingCLI 0.6.0 Release Prep

This note records the release-prep evidence for the `0.6.0` worktree-first release line.

Target version: `0.6.0`
Verification date: `2026-07-19`
Evidence directory: `/tmp/biucing-phase-e.u3FQny`

## Release Theme

`0.6.0` makes all shipped BiucingCLI templates worktree-ready.

The release claim is:

> Every generated starter can be developed, tested, and packaged from parallel Git worktrees without accidental cross-worktree interference.

## Scope

Templates covered:

- `frontend`
- `web-service`
- `microservice`
- `worker`
- `apple`
- `android`
- `harmonyos`

Primary changes since `0.5.0`:

- added the shared worktree isolation contract and collision audit;
- added `worktree` metadata to every `template.json`;
- exposed worktree metadata through `biucing list`, `biucing info`, JSON output, and `biucing validate`;
- implemented Docker-first isolation for Compose project names, Docker volumes, image tags, host ports, dependency stores, and caches;
- implemented native-template isolation for cache paths, local signing/config files, generated output, and debug app identity hooks;
- added `make worktree-info`, `make worktree-doctor`, and `make clean-worktree` to every generated starter.

## Known Limitations

- Phase E used Docker Compose config checks rather than heavyweight Docker image builds.
- Native Phase E checks used diagnostics and dry-run command expansion rather than real Xcode, Gradle, or hvigor builds.
- HarmonyOS keeps `AppScope/app.json5` stable by default; the requested debug bundle suffix is passed as a build property and should only be wired into bundle rewriting where the local DevEco toolchain supports it cleanly.

These limitations do not block the `0.6.0` worktree-first release claim because the repo-level tests and generated-project smoke checks verify the isolation contract surfaces without depending on workstation-specific SDK availability.
