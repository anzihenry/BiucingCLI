# BiucingCLI 0.8.0

`0.8.0` hardens every starter from project creation through runtime and release packaging.

## Highlights

- All seven templates now validate resolved inputs before creating files and expose the same `bootstrap`, `doctor`, `lint`, `test`, `verify`, `build`, `clean`, and `help` Make commands.
- The Frontend starter commits its pnpm lockfile and tests the production Nginx image in a real browser workflow.
- Web Service and Microservice starters enforce bounded timeouts, health checks, and graceful shutdown; Microservice also ships a real, tested protobuf `Ping` gRPC contract.
- Worker retry exhaustion, exponential backoff, cancellation, and scheduled-cycle behavior now have deterministic tests.
- Apple release workflows prevent worktree Bundle ID suffixes from entering signed archives and verify identity before signing and after archive creation.
- Android and HarmonyOS release flows validate dependency provenance, signing identity, and packaged artifacts before delivery.
- Apple, Android, and HarmonyOS templates now protect the documented credential and signing-material locations, with hardened temporary signing injection for HarmonyOS.

## Compatibility

Existing public `make` workflows remain available. The new common command names add a portable automation surface across templates. Invalid or template-incompatible create options now fail before a target directory is written instead of being accepted or silently ignored.

## Distribution Boundary

The release validates local generation, runtime contracts, signing inputs, and release artifacts. Real App Store Connect, Google Play, and AppGallery submissions still require product-specific accounts, application records, credentials, and review configuration; no store submission is claimed by this release.
