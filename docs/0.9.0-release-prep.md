# BiucingCLI 0.9.0 Release Prep

Target version: `0.9.0`

Verification date: `2026-09-07`

## Scope

`0.9.0` hardens distribution packaging, input resolution, expected CLI errors, atomic generation, and installed-artifact verification.

## Required Evidence

```bash
python3 -m unittest discover -s tests
uvx ruff==0.16.6 check --select E4,E7,E9,F src tests scripts
PYTHONPATH=src python3 -m biucingcli.cli validate
PYTHONPATH=src python3 -m biucingcli.cli list --json
./scripts/verify-distribution
git diff --check
```

## Artifact Contract

- Wheel and source distributions contain all seven template definitions.
- Hidden starter files and the Android Gradle wrapper JAR survive packaging.
- A clean virtual environment can run `list`, `validate`, and `create` outside the checkout.
- All seven templates generate successfully in non-interactive mode.
- Generated doctor scripts are executable and common `make help` targets work.
- Generated text contains no unresolved BiucingCLI placeholders.

## Error Contract

- Unknown templates and existing targets exit with code `2` and no traceback.
- Invalid bundled metadata exits with code `1` and no traceback.
- Generation I/O failures remove their staging directories and do not create the target.
- Unexpected programming failures remain visible to maintainers.

## Current Evidence

- Repository tests: 55 passing on Python 3.11, 3.12, 3.13, and 3.14.
- Installed distribution verification: wheel, source distribution, and all seven generated templates passing locally.
- Cross-version CI: passed on macOS for Python 3.11 through 3.14 in [GitHub Actions run 34115674721](https://github.com/anzihenry/BiucingCLI/actions/runs/34115674721).

## Known Boundaries

- The distribution gate verifies project generation and static starter contracts, not external SDK or container builds.
- Registry publication remains a separate release operation; local checkout installation is documented until a registry destination is selected.
