# Apple、Android、HarmonyOS 共同架构决策与差距清单

确认日期：2026-09-24。状态：四项决策已接受；已实现会话所有权、DI 反例和设备界面，完整设备验收仍待完成。

本文补充既有 A01–A20 基线，统一生命周期、多设备交互、验收口径和 DI 最低保证。
本次确认的要求以本文为准；实现和局部测试不等于所有设备已满足完整验收要求。
三端共享职责、依赖方向、C++20/C ABI 和二进制交付规则，不要求目录、壳数量或发布单元一致。

## D01：会话跟随业务所有者

会话由明确的业务页面、窗口或文档所有者持有；应用级对象共享工厂，不默认共享可变业务会话。
视图可见性与会话寿命分开管理。UI 回调只能表达事件，不能仅因暂时不可见就判定业务已结束。

| 场景 | 共同要求 |
| --- | --- |
| 重绘、旋转、布局切换 | 保留仍存活业务所有者的会话和状态，不重复创建核心 |
| 临时弹层、短暂遮挡 | 不仅因暂时不可见就关闭会话 |
| 进入后台 | 不直接销毁会话；任务继续、暂停或取消由业务策略及系统能力决定 |
| 明确退出业务、关闭窗口或文档 | 所有者拒绝新任务、请求取消、等待实际结束，再释放资源；重复关闭安全 |
| 新建独立窗口或文档 | 默认独立会话；需要共享的数据通过明确服务共享 |
| 进程终止后重启 | 重新创建会话；仅按产品需要恢复持久化状态，不恢复裸句柄或承诺续接执行中的任务 |

不要求系统终止进程时必能执行异步清理。需要可靠保存的数据必须由持久化策略保障。
导航退出与窗口关闭的具体事件映射由平台实现；应能观察关闭完成或错误，而不是仅证明发出了取消请求。

## D02：共享业务，按设备设计交互

| 边界 | 共同要求 |
| --- | --- |
| 核心 | 业务规则不按设备类型分支；设备能力由外层转换为明确输入或服务 |
| 功能状态 | 共享适用的用例、业务状态和类型化输出；焦点、滚动位置等交互状态归设备 UI |
| UI | 手机/平板适配触控和布局；电脑适配键鼠与窗口；手表适配短流程、圆屏和旋钮；电视适配遥控器和焦点 |
| 组装 | 壳或组装层选择功能、界面及平台服务；功能组件不自行查询全局设备环境 |
| 产品范围 | 各设备功能、发布节奏可不同；明确支持、暂不支持和不适用的功能 |
| 壳与模块 | 按系统入口、生命周期和发布需求拆分，不强制三端壳数量相同 |

HarmonyOS 可以保留一个 entry，手表和电视界面允许独立实现并通过公开工厂复用业务模型。
设备声明、字号和间距调整不等同于完成设备交互适配。共享状态不意味着跨设备自动同步。

## D03：支持状态按证据分级

| 阶段 | 必须具备的证据 | 对外表述 |
| --- | --- | --- |
| V1 架构纳入 | 功能范围、组件边界、平台接入方式明确 | 已纳入架构范围 |
| V2 构建通过 | 组件、应用和测试包构建及依赖/产物校验通过 | 已完成构建验证 |
| V3 运行通过 | 指定模拟器或真机执行核心调用、取消、关闭、隔离及生命周期场景 | 已在指定环境运行验证 |
| V4 设备适配通过 | 目标真机主要流程、输入、布局、无障碍、性能及功耗验收通过 | 已完成目标设备适配 |
| V5 发布就绪 | 正式签名、安装升级、分发要求和发布回归通过 | 可正式发布 |

记录必须包含源码/产物版本、系统版本、设备或模拟器型号、CPU 架构、工具链、构建类型、
执行场景、预期与实际结果、日志位置及未完成项。性能/功耗阈值按产品预先定义，本文不虚构统一数值。
编译不能代替运行，宿主转译不能代替 ArkTS VM，模拟器不能代替真机，Debug 不能代替 Release。
同一平台不同设备、ABI 和构建类型分别记录；有部分运行证据，不等于全部 V3 场景已经满足。
共同契约使用相同场景编号，各平台使用原生测试工具；设备特有交互单独验收。

## D04：统一 DI 最低保证，允许工具不同

- 显式构造或公开工厂注入；业务代码不访问全局服务容器。
- 组件发布前检查内部图，产品壳检查自身可见依赖；壳不扫描二进制 SDK 隐藏源码。
- 缺失依赖、重复绑定、非法环路及类型不匹配应阻断构建。
- 明确应用、业务会话和功能实例的所有者，避免长生命周期对象持有短生命周期会话。
- 取消、等待和关闭由业务所有者执行，不能仅依赖 DI 容器销毁。
- SDK 公开接口独立于 DI 工具；静态检查不到的部分明确记录并用针对性测试验证。

编译期检查、构建时执行的测试、设备行为测试须分别标注；测试通过不是完整的编译期证明。
Apple 保留 SafeDI，Android 保留 Dagger；HarmonyOS 保留显式构造与小型构造图生成器，
暂不引入 TheRouter 或 ArkDI，也不把现有生成器扩展成通用运行时容器。

### HarmonyOS 第三方选型依据

本轮调研检查的源码版本（不是对所有版本的结论）：

| 项目 | 检查版本 | 结论 |
| --- | --- | --- |
| TheRouter Harmony | `d90329c6ffc8ccdf37f424336ba89dcb48c3134a`，包版本 `1.0.3-rc3` | 按名称获取服务、缓存及模块扫描内重名检查；未确认完整构造图/业务会话作用域校验，不作为当前 DI 替代；保留路由候选资格 |
| ArkDI | `f48ddd98f0a9d556af866d9d46997a0c26a7deea`，包版本 `1.0.0` | 非 UI 原始源码转译后的宿主最小案例暴露嵌套解析、环路检测与同名 token 缓存问题，暂不采用 |

ArkDI 调研案例：A→B→A 得到栈溢出；同一 scope 下 B 的工厂通过 resolver 获取 A，
所得 A 与 scope 直接取得的 A 不同且未纳入该 scope 的释放；两个不同但同名的类 token 单例发生冲突。
另有 `close(): void` 不等待异步释放的能力差距。以上是宿主逻辑复现，不是 HarmonyOS 真机结果。
两个候选均未完成本项目字节码 HAR 无源码消费、Release/混淆和设备集成验收；不据此断言 HAR 不受支持。

[TheRouter 版本说明](https://therouter.cn/docs/2022/09/06/01)、
[ArkDI 仓库](https://gitcode.com/chenjz0369/arkdi)。
调研临时复现材料不作为长期 CI 证据；重新选型时须固定版本并保存可复现案例与日志。

## 当前实现与差距

下表已更新为本轮实现；构建、测试和未覆盖范围见[验证记录](cross-platform-architecture-verification.md)。
“待验证”表示缺少该项证据，不直接认定实现错误。

| 项目 | Apple | Android | HarmonyOS |
| --- | --- | --- | --- |
| 壳与设备 | iOS/macOS/watchOS/tvOS 四壳 | 手机/平板、Wear、TV 三壳 | 一个 entry，声明 phone/tablet/2in1/wearable/tv |
| 生命周期 | 四壳通过 StateObject 持有 SessionOwner/模型；显式 close 可等待，释放时兜底清理 | ViewModel 保留会话与业务任务；清除时停止模型、关闭 native；可等待完成并观察错误 | WindowStage 持有 SessionOwner，以局部存储注入模型；stage/ability 销毁才关闭 |
| 多设备交互 | 有四壳；不能据此宣称全部交互验收完成 | 有独立 Wear/TV UI 和旋钮/焦点等模拟器证据 | 已分 Mobile/Desktop/Watch/TV；键鼠、表冠及遥控器交互待设备验证，暂无应用内新建窗口入口 |
| DI | SafeDI 缺失/重复/环路反例及真实 Swift 类型反例；所有者行为有测试 | Dagger 四层图各验证四类反例；模型停止、关闭等待与所有者有测试 | 图反例和真实 ArkTS 壳构造类型反例；宿主测试作用域与关闭，仍无完整静态作用域证明 |
| 运行证据 | macOS 实机及其余三平台模拟器有核心/会话/资源测试；新增 D01 完整场景未验收 | 三壳有构建与模拟器证据，含 Activity 重建；新增完整共同场景仍需映射 | 核心宿主测试、HAR/HAP、设备测试包编译有记录；尚无 HarmonyOS 设备运行证据 |
| 支持口径 | 按既有场景描述运行结果，不能直接标为完整 V3/V4/V5 | 同左；ARMv7 编译不代表运行，Wear/TV Debug 运行不代替 Release | 已纳入五类设备范围并完成现有构建验证；不能宣称五类设备均已运行通过 |

源码入口：

- Apple：`Apps/{ios,macos,watchos,tvos}/Sources/ShellRoot.swift`、`Composition/Sources/AppComposition.swift`。
- Android：`composition/src/main/java/composition/SessionOwner.kt`。
- HarmonyOS：`components/homefeature/src/main/ets/HomeView.ets`、`composition/di.json`、`scripts/di`。

上述路径分别相对于 `src/biucingcli/template_data/{apple,android,harmonyos}/template/`。
共享核心示例尚无真实数据库、迁移、跨设备同步和长任务进度；这些不计为已统一实现的能力。

## 实施状态与验收条件

G01 的所有者实现及行为测试、G02 的 DI 反例、G03 的设备界面和范围矩阵、G04 的验收记录模板已落地。
下表保留完整完成条件；系统生命周期与设备交互证据未齐，不将这些条目整体标为验收完成。

| 编号/顺序 | 范围与待补内容 | 完成条件 |
| --- | --- | --- |
| G01 优先 | Apple/HarmonyOS 将会话所有权与视图显示回调解耦；Android 核对所有者边界 | L01–L05 场景通过，退出后无遗留核心任务，关闭可观测 |
| G02 优先 | 三端列明 DI 静态保证与缺口，补嵌套依赖和作用域反例 | I01–I04 场景有逐端证据；每项标注检查阶段，未覆盖项可见 |
| G03 后续 | HarmonyOS 按设备组织交互，三端补功能/能力矩阵 | 每类设备记录支持范围；M01 按目标设备执行，未验证项不标完成 |
| G04 贯穿 | 建立按设备、版本和构建类型的验收记录 | V01 记录完整；HarmonyOS 首先取得真实平台运行证据，再开展 V4/V5 |

| 场景 | 验收断言 |
| --- | --- |
| L01 保留 | 重绘/配置变化/临时遮挡前后仍为同一业务会话，结果不丢失，不重复创建核心 |
| L02 后台 | 应用执行明确的后台任务策略；不会单因不可见销毁仍有效的业务会话 |
| L03 退出 | 退出后拒绝新任务，取消活动任务，实际结束后释放；重复关闭安全，错误可观测，旧回调不污染新页面 |
| L04 隔离 | 两个独立所有者的会话及状态不同；关闭其中一个不影响另一个；应用工厂可共享 |
| L05 重启 | 进程重启创建新会话；不复用句柄；仅恢复声明支持的持久化状态（示例无持久化时标不适用） |
| I01 构建失败 | 缺失/重复绑定、非法环路、错误构造类型分别按预期原因阻断组件或壳构建 |
| I02 嵌套作用域 | 同一会话内直接和嵌套依赖获得同一受管实例；跨会话不同；长寿命对象不捕获已结束会话 |
| I03 释放责任 | 有在途任务时关闭仍等待真实结束；每个受管资源只释放一次，嵌套依赖不遗漏 |
| I04 交付边界 | 已发布组件无源码仍可组装；公开 API 不暴露 DI 类型；描述与真实接口不一致时构建失败 |
| M01 设备交互 | 按设备执行触控/布局、键鼠/窗口、圆屏/旋钮或遥控器/焦点，以及对应无障碍检查；记录不适用项 |
| V01 证据 | 按 V1–V5 记录环境、版本、结果和待办；不把历史局部测试提升为新增契约全部通过 |
