## Phase B: Unified Worktree Identity

### Goal

Make all seven templates use one identity model.

### Tasks

1. Add `WORKTREE_LABEL` to every generated Makefile.
2. Normalize `WORKTREE_ROOT` to:
   ```make
   WORKTREE_ROOT ?= $(shell git rev-parse --show-toplevel 2>/dev/null || pwd)
   ```
3. Normalize `WORKTREE_ID` to an 8-character hash of `WORKTREE_ROOT`.
4. Keep `WORKTREE_ID` overridable.
5. Make `WORKTREE_SLUG` use the template runtime name plus `WORKTREE_ID`.
6. Update every `worktree-info` target to print:
   - `WORKTREE_ROOT`;
   - `WORKTREE_LABEL`;
   - `WORKTREE_ID`;
   - `WORKTREE_SLUG`.
7. Update README guidance and tests.

### Acceptance Criteria

- Docker-first and native templates use the same identity formula.
- Generated projects still support explicit `WORKTREE_ID=...` overrides.
- Tests cover the identity model for all templates.

### Status

Complete for unified identity.

Implementation notes:

- all seven templates now expose `WORKTREE_LABEL`;
- native templates now use the same git-root plus path-hash `WORKTREE_ID` model as Docker-first templates;
- `WORKTREE_ID` remains explicitly overridable;
- generated README guidance now distinguishes human-readable labels from hash-based isolation IDs.

### Verification

```bash
python3 -m unittest discover -s tests
PYTHONPATH=src python3 -m biucingcli.cli validate
```

Generate at least one Docker-first and one native project and run:

```bash

```

## Phase C: Port Conflict Advisor

### Goal

Make Docker-first templates detect occupied host ports and print useful override suggestions.

### Tasks

1. Add a small Makefile-level port check pattern.
2. Check frontend ports:
   - `DEV_HOST_PORT`;
   - `HOST_PORT`.
3. Check web-service ports:
   - `HOST_PORT`.
4. Check microservice ports:
   - `HOST_HTTP_PORT`;
   - `HOST_GRPC_PORT`;
   - `HOST_DEPENDENCY_STORE_PORT`;
   - `HOST_OTEL_GRPC_PORT`;
   - `HOST_OTEL_HTTP_PORT`.
5. Keep worker explicit that it publishes no host ports by default.
6. Print copy-pasteable override examples.

### Acceptance Criteria

- Occupied ports produce warnings before a dev service is started.
- Suggestions do not auto-edit local files.
- Existing default-port warnings remain understandable.

### Status

Complete for Docker-first port advice.

Implementation notes:

- `frontend`, `web-service`, and `microservice` now use `lsof` when available to detect occupied published host ports;
- occupied ports print copy-pasteable override suggestions;
- checks are advisory only and do not edit Makefiles, Compose files, or local environment files;
- `worker` remains explicit that it publishes no host ports by default.

### Verification

```bash

PYTHONPATH=src python3 -m biucingcli.cli validate
```

## Phase D: Stronger Docker Runtime Doctor

### Goal

Make Docker-first templates expose a non-invasive Compose config check.

### Tasks

1. Add `worktree-compose-config` to templates that use Compose.
2. Make the target run `docker compose -f $(DEV_COMPOSE_FILE) config` through the worktree-aware `$(COMPOSE)` wrapper.
3. Make `worktree-doctor` call or clearly point to the config target.
4. Preserve behavior when Docker is unavailable by reporting a clear diagnostic.
5. Update generated README guidance and tests.

### Acceptance Criteria

- Compose config can be rendered without starting containers.
- The rendered config uses the current `COMPOSE_PROJECT_NAME`.
- The command is available in `frontend`, `web-service`, `microservice`, and `worker`.

### Status

Complete for Docker-first Compose diagnostics.

Implementation notes:

- `frontend`, `web-service`, `microservice`, and `worker` now expose `make worktree-compose-config`;
- the target renders `docker compose config` through the worktree-aware `$(COMPOSE)` wrapper;
- `worktree-doctor` points users to the config target without forcing Docker usage on every doctor run;
- missing Docker produces a clear diagnostic from the config target.

### Verification

### Acceptance Criteria

- The supported/deferred boundary is explicit.

## Risk Register

| Risk | Mitigation |
| --- | --- |
| Hash-based IDs are less readable than directory names | add `WORKTREE_LABEL` for humans and keep `WORKTREE_ID` for isolation |
| Users want semantic IDs | keep `WORKTREE_ID` overridable |
| Port checks become platform-specific | prefer `lsof` when available and degrade to clear warnings when not |
| Diagnostics become too slow | keep checks local, non-invasive, and container-free |
| Compose config checks fail when Docker is absent | report the missing tool clearly rather than hiding the failure |
| Native real-build evidence is environment-dependent | separate static, doctor, and real-build tiers |
| HarmonyOS bundle rewriting is unsafe | keep the 0.6.0 stable-source approach and document the deferred boundary |
