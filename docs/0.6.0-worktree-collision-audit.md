# BiucingCLI 0.6.0 Worktree Collision Audit

This audit records the current template state before Phase B implementation.

Scope:

- `frontend`;
- `web-service`;
- `microservice`;
- `worker`;
- `apple`;
- `android`;
- `harmonyos`.

This is an audit only.
It intentionally does not change template implementation.

## Classification

| Class | Meaning |
| --- | --- |
| Blocking | Must be addressed for `0.6.0` to claim worktree-first support |
| Important | Should be addressed during `0.6.0`, but can be documented if platform constraints block full implementation |
| Optional | Useful follow-up that does not block the main release thesis |

## Cross-Template Findings

### Blocking

- No template currently exposes `make worktree-info`, `make worktree-doctor`, or `make clean-worktree`.
- No template currently declares worktree support in `template.json`.
- Docker-first templates do not consistently pass `COMPOSE_PROJECT_NAME`, so runtime resources depend on Docker Compose defaults or hard-coded names.
- Several templates publish fixed host ports by default, which prevents two worktrees from running dev services side by side.

### Important

- Runtime image tags generally default to `latest`, so multiple worktrees for the same generated project can overwrite each other's image reference.
- Native app identities are mostly fixed after generation, so parallel simulator/emulator/device installs can overwrite one another.
- Current cleanup commands are generic (`clean`, `down`, or tool-specific cleanup) rather than scoped explicitly to current-worktree runtime state.

### Optional

- Phase B can start with metadata values marked `planned` before implementation changes move templates to `partial` or `worktree-ready`.
- Port auto-selection should remain deferred unless explicit port variables and diagnostics prove insufficient.

## Detailed Findings

### `frontend`

Current relevant files:

- `templates/frontend/template/Makefile`;
- `templates/frontend/template/compose.dev.yaml`;
- `templates/frontend/template/.gitignore`;
- `templates/frontend/template/.dockerignore`.

Collision points:

- dev server publishes `5173:5173`;
- `DEV_PORT` exists in the Makefile, but Compose uses literal `5173`;
- runtime `docker-run` publishes `8080:80` by default;
- named Docker volumes are fixed:
  - `frontend-node-modules`;
  - `frontend-pnpm-store`;
  - `frontend-playwright-cache`;
- runtime image defaults to `{{PACKAGE_NAME}}:latest`;
- no diagnostic target explains which port, volume, image, or cache belongs to the current worktree.

Required Phase C outcome:

- Compose port mapping must use an overridable host port;
- named volumes must be scoped by Compose project or worktree-specific names;
- image ref must be worktree-aware by default;
- `worktree-info` must show dev port, runtime port, Compose project name, image ref, and cache volumes.

### `web-service`

Current relevant files:

- `templates/web-service/template/Makefile`;
- `templates/web-service/template/compose.dev.yaml`;
- `templates/web-service/template/compose.yaml`;
- `templates/web-service/template/.gitignore`;
- `templates/web-service/template/.dockerignore`.

Collision points:

- dev Compose publishes `{{HTTP_PORT}}:{{HTTP_PORT}}`;
- runtime Compose publishes `{{HTTP_PORT}}:{{HTTP_PORT}}`;
- runtime `docker-run` maps host port to container port with default `{{HTTP_PORT}}`;
- named Docker volumes are fixed:
  - `web-service-go-build`;
  - `web-service-golangci-lint`;
- runtime image defaults to `{{SERVICE_NAME}}:latest`;
- Makefile sets `GOCACHE` and `GOLANGCI_LINT_CACHE` under `.cache`, but `.gitignore` does not ignore `.cache/`.

Required Phase C outcome:

- pass `COMPOSE_PROJECT_NAME` for every Compose command;
- make host port override visible and consistent across dev, run, and runtime Compose;
- isolate Go/lint volumes;
- make `IMAGE_REF` worktree-aware by default;
- add `.cache/` ignore coverage or move caches to an already ignored path.

### `microservice`

Current relevant files:

- `templates/microservice/template/Makefile`;
- `templates/microservice/template/compose.dev.yaml`;
- `templates/microservice/template/deploy/compose.yaml`;
- `templates/microservice/template/.gitignore`;
- `templates/microservice/template/.dockerignore`.

Collision points:

- dev Compose publishes fixed generated ports for HTTP and gRPC;
- dependency store publishes fixed generated dependency port;
- OTel collector publishes fixed `4317` and `4318`;
- deployment Compose repeats HTTP, gRPC, dependency-store, and OTel host ports;
- named Docker volumes are fixed:
  - `microservice-go-build`;
  - `microservice-golangci-lint`;
- runtime image defaults to `{{SERVICE_NAME}}:latest`;
- dependency store resources rely on Compose defaults rather than explicit worktree identity.

Required Phase C outcome:

- expose and document all host port overrides:
  - HTTP;
  - gRPC;
  - dependency store;
  - OTel gRPC;
  - OTel HTTP;
- pass `COMPOSE_PROJECT_NAME`;
- make cache volumes and runtime images worktree-aware;
- verify `postgres` and `redis` variants.

### `worker`

Current relevant files:

- `templates/worker/template/Makefile`;
- `templates/worker/template/compose.dev.yaml`;
- `templates/worker/template/.gitignore`;
- `templates/worker/template/.dockerignore`.

Collision points:

- dev image is fixed as `{{WORKER_NAME}}-dev:latest`;
- runtime image defaults to `{{WORKER_NAME}}:latest`;
- Go build cache volume is fixed as `worker-go-build-cache`;
- long-running scheduled workers can overlap if two worktrees share Compose project defaults.

Required Phase C outcome:

- pass `COMPOSE_PROJECT_NAME`;
- make dev image, runtime image, and Go cache volume worktree-aware;
- add diagnostics for run mode, tick interval, shutdown timeout, image ref, and cache volume;
- preserve current `scheduled` and `oneshot` generated behavior.

### `apple`

Current relevant files:

- `templates/apple/template/Makefile`;
- `templates/apple/template/.gitignore`;
- `templates/apple/template/App/Project.swift`.

Current strengths:

- `.gitignore` already covers common local outputs:
  - `.build`;
  - `.cache`;
  - `DerivedData`;
  - `Tuist/.cache`;
  - `Tuist/Dependencies`;
  - generated Xcode project/workspace files;
  - `xcuserdata`.

Collision points:

- `xcodebuild` does not set `-derivedDataPath`;
- bundle ID is fixed as `{{BUNDLE_IDENTIFIER}}`;
- test bundle ID is fixed as `{{BUNDLE_IDENTIFIER}}.tests`;
- simulator installs from two worktrees can overwrite each other when using the same generated bundle ID;
- there is no target that prints DerivedData, bundle ID, or Tuist cache decisions.

Required Phase D outcome:

- add worktree diagnostics;
- set or document worktree-aware DerivedData;
- support or document debug bundle ID suffix behavior;
- keep Tuist/Xcode generated output local to the worktree.

### `android`

Current relevant files:

- `templates/android/template/Makefile`;
- `templates/android/template/.gitignore`;
- `templates/android/template/app/build.gradle.kts`.

Current strengths:

- `.gitignore` covers:
  - `.gradle/`;
  - `build/`;
  - module build outputs;
  - `local.properties`;
  - IDE files;
- release signing data is loaded from local properties or environment variables;
- debug builds already use `applicationIdSuffix = ".debug"`.

Collision points:

- debug suffix is fixed, so two worktrees install the same debug application ID;
- Gradle user home and cache choices are not visible;
- `local.properties` is local but not included in diagnostics;
- emulator/device install behavior is not worktree-aware.

Required Phase D outcome:

- add worktree diagnostics;
- make debug application ID suffix worktree-aware or explicitly overridable;
- report local Gradle cache and `local.properties` status;
- document whether project-local Gradle user home is default or opt-in.

### `harmonyos`

Current relevant files:

- `templates/harmonyos/template/Makefile`;
- `templates/harmonyos/template/.gitignore`;
- `templates/harmonyos/template/AppScope/app.json5`;
- `templates/harmonyos/template/build-profile.json5`;
- `templates/harmonyos/template/scripts/release-build`.

Current strengths:

- `.gitignore` covers:
  - `.hvigor/`;
  - `.ohpm/`;
  - `build/`;
  - `entry/build/`;
  - `node_modules/`;
  - `oh_modules/`;
  - `local.properties`;
  - packaged outputs;
  - logs;
- `release-build` fails fast when `local.properties` is missing;
- signing material is local-only and not committed.

Collision points:

- app bundle name is fixed as `{{BUNDLE_NAME}}`;
- build and package outputs are local but not diagnosed;
- local signing status is only visible during release flow;
- parallel installed debug identity is not documented.

Required Phase D outcome:

- add worktree diagnostics;
- report `.hvigor`, `.ohpm`, `oh_modules`, build output, and local signing file status;
- document debug bundle-name suffix as supported only after DevEco/hvigor verification, otherwise explicitly defer it.

## Metadata Recommendation For Phase B

Phase B should add the following metadata to all templates with `support_level` initially set to `planned`.

```json
{
  "worktree": {
    "support_level": "planned",
    "isolation_dimensions": [
      "diagnostics",
      "cleanup"
    ],
    "diagnostics": [
      "make worktree-info",
      "make worktree-doctor"
    ],
    "cleanup": [
      "make clean-worktree"
    ]
  }
}
```

## Phase A Decision Summary

The `0.6.0` worktree-first theme is viable and well aligned with the current template portfolio.

The most important implementation order is:

1. add metadata and validation so worktree support becomes visible;
2. fix Docker-first runtime collisions, where parallel worktree pain is most immediate;
3. fix native cache and app identity collisions, with platform-specific caution;
4. update release evidence so future changes cannot silently regress worktree behavior.

No current template is worktree-ready yet.
That is expected at the end of Phase A.
